# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend hardening. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual shadcn-style components) |
| Preset | not applicable |
| Component library | none (custom components using CVA + cn utility) |
| Icon library | lucide-react v0.564 |
| Font | Geist, Arial, Helvetica, sans-serif |

Components already in project: `Button` (6 variants, 4 sizes), `Card` (Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter). New components this phase: `ProgressBar`, `Badge`, `Skeleton`, `ErrorBoundary`, `DocumentCard`, `DropZone`, `ThemeToggle`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, inline spacing |
| sm | 8px | Compact element spacing, button icon gaps, card badge row gaps |
| md | 16px | Default element spacing, card internal padding, form field gaps |
| lg | 24px | Section padding, card content padding (existing Card uses p-6 = 24px) |
| xl | 32px | Layout gaps between major sections, page side padding |
| 2xl | 48px | Page top/bottom padding, major section breaks |
| 3xl | 64px | Not used this phase |

Exceptions: Touch target minimum 44px for mobile sidebar nav items and retry button (accessibility).

## Color

The project uses CSS custom properties for all semantic colors. Values below are the light-mode defaults; dark-mode values are already defined in globals.css and will be migrated from `@media (prefers-color-scheme: dark)` to `.dark` class selector.

### Semantic Token Palette

| Role | Light Value | Dark Value | CSS Variable | Usage |
|------|-------------|------------|-------------|-------|
| Background (60%) | `#fdfdfd` | `#09090b` | `--background` | Page backgrounds, main content area |
| Card (30%) | `#ffffff` | `#09090b` | `--card` | Document cards, upload section, sidebar, modals |
| Muted | `#f4f4f5` | `#27272a` | `--muted` | Skeleton loading, disabled backgrounds, secondary surfaces |
| Primary | `#18181b` | `#fafafa` | `--primary` | Primary CTA buttons, active nav indicator, links |
| Destructive | `#ef4444` | `#7f1d1d` | `--destructive` | Delete button, error banners |
| Border | `#e2e8f0` | `#27272a` | `--border` | Card borders, dividers, sidebar border |

### Status Colors (direct Tailwind, not CSS variables)

| Status | Light | Dark | Usage |
|--------|-------|------|-------|
| Success (green) | `bg-green-100 text-green-700` | `bg-green-900/30 text-green-400` | COMPLETED badge |
| Error (red) | `bg-red-100 text-red-700` | `bg-red-900/30 text-red-400` | FAILED badge, error banner background |
| Warning (yellow) | `bg-yellow-100 text-yellow-700` | `bg-yellow-900/30 text-yellow-400` | Processing/PENDING badge |
| Info (blue) | `bg-blue-100 text-blue-700` | `bg-blue-900/30 text-blue-400` | Language badge, progress bar accent |
| Accent (violet) | `bg-violet-100 text-violet-700` | `bg-violet-900/30 text-violet-400` | Model badge |

### 60/30/10 Split

- **60% Dominant:** `bg-background` -- page body, main content area
- **30% Secondary:** `bg-card` -- document cards, sidebar, upload section, settings forms
- **10% Accent:** `bg-primary` -- reserved for: primary CTA buttons (Upload, Retry), active sidebar nav indicator, progress bar fill during translation phase, link text hover states

Accent is NOT used for: card backgrounds, borders, loading states, or decorative elements.

### Dark Mode Migration

Current globals.css uses `@media (prefers-color-scheme: dark)` which only responds to system preference. This phase must:
1. Add `@custom-variant dark (&:where(.dark, .dark *));` to globals.css
2. Duplicate dark variable block under `.dark` selector (in addition to the media query for system-default fallback)
3. Audit all pages for hardcoded slate colors (e.g., `bg-slate-50/30`, `text-slate-800`, `border-slate-200/50`) and replace with semantic tokens (`bg-background`, `text-foreground`, `border-border`)

## Copywriting Contract

### Primary Actions

| Element | Copy | Context |
|---------|------|---------|
| Upload CTA | "Upload PDF" | Inside drag-and-drop zone |
| Drag zone idle | "Drag and drop a PDF here, or click to browse" | DropZone component, idle state |
| Drag zone active | "Drop your PDF here" | DropZone component, file hovering over zone |
| Retry CTA | "Retry" | Failed document card, inline error banner |
| Details CTA | "Details" | Failed document card, expands error detail |
| Open Reader CTA | "Open Reader" | Completed document card footer |

### Empty States

| Page | Icon | Heading | Body |
|------|------|---------|------|
| Home (no documents) | `FileText` (lucide) | "No documents yet" | "Upload a PDF above to start translating." |
| Library (no documents) | `Library` (lucide) | "Your library is empty" | "Upload a PDF from the Home page to get started." |
| Reader (no translations) | `Languages` (lucide) | "No translations available" | "This document hasn't been translated yet." |
| Settings (no saved keys) | `Key` (lucide) | "No API keys saved" | "Add an API key to start translating documents." |

### Progress Labels

| Pipeline Phase | Label | Bar Behavior |
|----------------|-------|-------------|
| `extracting` | "Extracting..." | Indeterminate pulse animation |
| `generating_context` | "Generating Context..." | Indeterminate pulse animation |
| `translating` | "{translated_count}/{total_count} segments -- {percentage}%" | Determinate fill with spring animation |
| `null` (PENDING) | "Queued..." | Indeterminate pulse animation |
| INTERRUPTED | "Resuming..." | Indeterminate pulse animation |

### Error Messages

| Error Code | User-Facing Message |
|------------|-------------------|
| `LLM_AUTH_FAILED` | "Invalid API key. Check your key in Settings." |
| `LLM_RATE_LIMITED` | "Rate limit exceeded. Wait a moment and retry." |
| `LLM_CONTENT_POLICY` | "Some content was blocked by the AI provider's safety filters." |
| `PIPELINE_ERROR` | "Translation failed due to an internal error." |
| (unknown/missing) | "Translation failed. Try again or contact support." |

### Error Banner (Failed Document Card)

- Background: `bg-red-50 dark:bg-red-950/30`
- Border: `border-red-200 dark:border-red-800`
- Text: mapped error message from table above
- Actions: `[Retry]` button (primary style, compact) + `[Details]` button (ghost style, compact)
- Details expanded: raw `error_message` from API in `text-xs text-muted-foreground` monospace

### Partial Results Banner (Reader Page)

- Copy: "{count} segments were blocked by content filters. Available translations are shown below."
- Style: `bg-yellow-50 dark:bg-yellow-950/30 border-yellow-200 dark:border-yellow-800`
- Position: top of Reader page, full width, dismissible with X button
- Blocked segments in translation panel: show italic placeholder "Content blocked by safety filters" in `text-muted-foreground`

### Error Boundary Fallback

- Heading: "Something went wrong"
- Body: "An unexpected error occurred on this page."
- CTA: "Reload Page" (primary button, calls `window.location.reload()`)
- Layout: centered vertically and horizontally, `AlertTriangle` icon (lucide) above heading

### Destructive Actions

| Action | Trigger | Confirmation |
|--------|---------|-------------|
| Delete document | Trash icon on card hover | Browser `confirm()` dialog: "Are you sure you want to permanently delete this document and its translations?" (existing pattern -- will be replaced by optimistic delete with undo in React Query, no confirmation dialog) |
| Logout | Sidebar logout button | No confirmation (instant, existing pattern) |

### Network Error (Inline)

- Copy: "Couldn't load documents. [Retry]"
- Style: replaces content area where data would appear, `text-muted-foreground`, Retry is `text-primary` link
- No toasts, no global banners

### Interaction States

| Component | States | Transitions |
|-----------|--------|-------------|
| DocumentCard | idle -> hover (shadow lift, border highlight) -> click (navigate) | `hover:shadow-lg hover:-translate-y-1` via Tailwind, 300ms duration (existing) |
| ProgressBar (indeterminate) | continuous pulse | `animate-pulse` Tailwind utility on primary-colored bar |
| ProgressBar (determinate) | width animates to percentage | framer-motion spring: `stiffness: 100, damping: 20` |
| DropZone | idle -> dragover (border highlight, icon swap) -> drop (file processing) | Border: `border-dashed border-2 border-muted` -> `border-primary` on dragover |
| Sidebar (mobile) | hidden -> slide in from left with backdrop | framer-motion `AnimatePresence`, slide from x: -100% to x: 0, backdrop opacity 0 to 0.5 |
| Sidebar (desktop) | expanded (w-64) -> collapsed (w-16) | Tailwind `transition-all duration-300` (existing) |
| Error banner | hidden -> visible on FAILED status | No animation, immediate render |
| Card delete | visible -> optimistic removal -> rollback if error | React Query optimistic update, no animation on removal |

## Skeleton Loading Patterns

| Page | Skeleton Layout |
|------|----------------|
| Home | 3-column grid of card skeletons (matching document card dimensions): header bar (h-4 w-24), title bar (h-5 w-3/4), date bar (h-3 w-16), footer divider + link bar |
| Library | Existing skeleton grid (already good per CONTEXT.md) -- keep as-is, ensure consistent with shared Skeleton primitive |
| Reader | Two-pane skeleton: left pane (h-full w-1/2 bg-muted), right pane (3 text line skeletons at varied widths) |
| Settings | Form skeleton: 3 groups of label bar (h-4 w-20) + input bar (h-10 w-full), spaced at 24px |

Skeleton implementation: shared `Skeleton` component -- a `div` with `animate-pulse bg-muted rounded-md` that accepts `className` for sizing. Pages compose skeletons by arranging Skeleton primitives in their layout shape.
